# 🐧 Linux System Logs Analysis

## 🎯 Objectives

* 🔍 Explore and analyze authentication, runtime, and system logs on a Linux host.
* 🚨 Investigate SSH brute-force attempts and backdoor user creation via `auth.log`.
* 📦 Examine system and package manager logs to identify installed software and suspicious activity.
* 📜 Recover attacker commands from Bash history files across user accounts.
* 🛡️ Use `auditd` to detect process execution, file access, and network scanning activity through runtime monitoring.

---

## 🛠️ Tools & Resources

### 📄 Linux Logs

Analyzed key Linux log files including:

* `syslog` – General system activity and services
* `auth.log` – Authentication and user management events
* `kern.log` – Kernel-related messages
* Package manager logs – Software installation and update history

### 🖥️ Bash History

* Per-user command history files (`.bash_history`)
* Used to recover previously executed interactive commands

### 🔎 Auditd

* Linux auditing framework for runtime monitoring
* Tracks:

  * Process creation
  * File access
  * Network-related activities
* Enables investigations using custom audit keys

## 📚 Key Learnings

Linux logging requires a **layered investigation approach**, as no single log source provides the complete picture.

* 🔐 Authentication logs reveal login attempts and user management activity.
* 📜 Bash history helps recover attacker commands executed interactively.
* 🛡️ Auditd provides visibility into runtime behavior such as process execution, file access, and network activity.

In real-world Security Operations Centers (SOCs), these logs are typically ingested into SIEM platforms such as:

* 📊 Splunk
* 📈 Elastic Stack (ELK)

These platforms enable:

* Correlation of events across multiple log sources
* Automated alerting
* Dashboards and visualizations
* Faster investigations compared to manual `grep`-based analysis

Understanding Linux log sources and audit keys forms essential groundwork for effective threat hunting, incident response, and SOC operations.
