# 🚨 Escalation Guide (SOC L1 → L2 Process)

## 📌 Overview
This folder contains my SOC alert escalation workflow as an L1 Security Analyst.  
It shows how I analyze alerts, document findings, and escalate them to L2 when required.

---

## 🔄 Workflow Summary

As an L1 analyst, after completing alert triage and writing my report, I decide whether the alert needs to be escalated to L2 or not.

---

## 🔼 When I Escalate an Alert

I escalate an alert if:

- 🚨 It indicates a **major cyberattack** that needs deeper investigation  
- 🛠️ It requires **remediation actions** like malware removal, host isolation, or password reset  
- 📢 It requires communication with **customers, partners, management, or law enforcement**  
- ❓ I do not fully understand the alert and need senior analyst support  

---

## 🪜 My Escalation Steps

1. 🔍 I move the alert status to **"In Progress"**  
2. 🧪 I perform initial analysis and investigation  
3. 📝 I write a clear **alert report with my verdict (True Positive / False Positive)**  
4. 📤 If escalation is required:
   - I assign the alert to the **L2 analyst on shift**
   - 💬 I notify L2 via corporate chat or internal communication tool  
5. 👨‍💻 L2 receives the alert and continues deeper investigation  

---

## 🧠 What L2 Does Next

Once I escalate an alert, the L2 analyst:

- 📖 Reviews my report  
- ✅ Validates the alert (True Positive / False Positive)  
- 🔬 Performs deeper investigation  
- 🤝 Coordinates with other teams if needed  
- 🚨 Initiates Incident Response for major incidents  

---

## ⚠️ Important Notes

- 👍 I can always request L2 support if something is unclear  
- 🧑‍🎓 It’s better to ask than incorrectly close an alert  
- 📄 I always ensure my report is complete before escalation
